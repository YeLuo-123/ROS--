# 教材质量检查清单

## A. 定位与结构

- [ ] 明确所属分册、章节、读者和预计学时。
- [ ] 内容未越过三册边界，必要的跨册内容已有引用说明。
- [ ] 学习目标可观察、可评价，并与小结和习题对应。
- [ ] 学习目标与培养方案毕业要求的映射真实、克制，并使用K/A/D/T/E/C/L能力标签。
- [ ] 章节从问题或现象出发，而非从命令清单出发。
- [ ] 已核对 `references/project-decisions.md`，未改变已批准的课程、版本、案例和出版决策。
- [ ] 章节与《机器人操作系统与智能机器人开发》的书名承诺一致，明确体现感知、决策、执行、反馈或系统集成中的实际作用。

## B. 技术正确性

- [ ] ROS1、ROS2和共同概念标注清楚。
- [ ] 操作系统、ROS发行版和依赖环境明确。
- [ ] 包名、接口、消息类型、字段、命令和文件路径已核实。
- [ ] 代码标明已运行、静态审查、示意或待验证状态。
- [ ] 预期输出真实可观察，没有虚构测试数据。
- [ ] 易变化事实已用官方一手来源重新核验。

## C. 教学有效性

- [ ] 先修知识充分，不突然引入未讲概念。
- [ ] 抽象概念配有系统图、观察任务或最小实例。
- [ ] 每个关键操作说明“为什么做”和“看到什么”。
- [ ] 至少包含一个典型错误和完整排查路径。
- [ ] 实验可在给定课时、设备和环境中实施。
- [ ] “智能”对应可观察的自主性、反馈、规划、感知或决策能力，不以术语堆叠或单纯调用AI模型代替。
- [ ] 第一册内容沿TurtleMission统一代码基线递进，明确本章新增能力，并保留此前版本可复现性。
- [ ] 第一册第1至5章未提前安排完整案例；第6至9章依次且各自完整呈现TurtleGoal、TurtleGuard、TurtlePainter和TurtleMission；第10章未新增或重复包装第五个案例。

## D. 双语与表达

- [ ] 首次出现的术语符合“中文（English，缩写）”规范。
- [ ] 同一概念译名一致，技术标识符未被错误翻译。
- [ ] 中文表达简洁准确，英文内容服务于专业学习。
- [ ] 图题、表题、公式、单位和符号格式统一。
- [ ] 每章包含Technical English栏目，PPT以中文呈现。
- [ ] 未机械地将图题、表题和习题制作成中英双语；英文内容均有明确教学目的。

## E. 图、代码与引用

- [ ] 图表清晰标注方向、接口、坐标系或数据类型。
- [ ] 引用、改绘、自绘及授权状态明确。
- [ ] 代码来源、许可证和修改范围明确。
- [ ] 参考资料可追溯，优先官方文档、标准和原始论文。
- [ ] 未使用软件截图；操作界面以文字路径或自绘图表达。
- [ ] GitHub仓库、分支、代码许可证和第三方模型许可证已核实。
- [ ] 原创教材内容与原创代码分别应用CC BY 4.0和Apache-2.0，仓库根目录已解释许可边界。
- [ ] 第三方代码、数据、模型、权重和素材未被重新授权，归属、来源、修改和原许可证可追溯。

## F. 习题与案例

- [ ] 习题覆盖理解、操作、实现、诊断和设计中的适用层级。
- [ ] 答案与评分点已同步复核。
- [ ] 案例信息类别和复现等级标注清楚。
- [ ] 竞赛案例不是宣传稿，包含失败、限制和教学复现路径。
- [ ] 第三册案例标明适用课程、建议学时、先修知识、人员规模、设备和教师准备。
- [ ] `P+D`案例分别提供生产实习和综合课程设计路线，而不是更换标题后复用同一任务。
- [ ] 生产实习路线包含安全、部署、操作、调试、日志和交接要求。
- [ ] 综合课程设计路线包含需求、方案评审、阶段检查、系统测试、报告和答辩。
- [ ] 两门课程分别设置提交物和评分量规。
- [ ] 第三册综合案例给出环境、感知输入、决策逻辑、执行机构、反馈证据和验收指标的完整闭环。
- [ ] 第一册期末TurtleMission覆盖目标输入、位姿感知、决策控制、安全约束、任务反馈、异常处理、记录诊断和运行评价，且未越界引入第二册主题。

## G. 交付状态

- [ ] 列出已完成内容。
- [ ] 列出建议性设计。
- [ ] 列出待核实事实、待运行代码和待授权素材。
- [ ] 清除无说明的TODO、占位符和断开的交叉引用。
